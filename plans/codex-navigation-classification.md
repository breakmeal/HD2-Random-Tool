## Current State

- `.enemy-focus` 使用 `position: fixed; inset: 0`，因此敌人详情遮罩覆盖整个视口，包含左侧 12.5% 的“超级地球”返回舞台。
- 顶部 `.tabs` 同时包含随机部署、军备库、装备图鉴、资料与译名；敌人入口单独固定在右侧。
- 图鉴当前只有原始装备类型下拉框：主武器、次要武器、投掷物、战略配备和强化剂，没有战略配备用途分类。
- `data.js` 的战略配备已有 `offensive`、`defensive`、`support`、`backpack`、`vehicle` 标签；名称可可靠区分 Orbital/Eagle、自动岗哨和人工阵地。
- 当前共 199 件装备，其中战略配备 89 件；未发布战争债券仍由 `released()` 排除在随机池之外。

## Implementation Plan

1. 将敌人详情层从视口固定定位改为相对 `.enemy-overlay` 的绝对定位，并回归验证左侧返回入口。
2. 在 `codex-v2.js` 建立唯一分类函数和分类定义；对 199 件装备做完整性/互斥校验，并替换旧类型筛选。
3. 修改 `index.html` 导航结构：顶部只保留随机部署和军备库；新增右侧入口列承载装备图鉴、资料与译名、敌人。
4. 修改 `app.js` 的面板激活逻辑，使顶部标签和右侧入口使用同一 `data-tab` 协议并同步激活态。
5. 在 `interface-refresh.css` 中实现分类组、右侧入口列和响应式样式，更新文档并执行浏览器验证。

## Decisions

- 2026-08-08 — 决定：MS-11 单兵导弹井归入“需要角色操控的战备”。
  - 原因：它需要角色使用手持目标遥控器，不属于轨道、飞鹰或自动炮塔。
  - 影响：原 `offensive` 标签不直接等同于红色战备分类。
- 2026-08-08 — 决定：地雷、护盾中继器和特斯拉塔归入绿色“炮塔战备”组。
  - 原因：用户要求绿色只分自动部署与角色操控两类；这些装备部署后自动生效，不需要角色持续操控。
  - 影响：“炮塔战备”在代码中代表自动部署型绿色战备，范围比名称中的枪械炮塔稍广。
- 2026-08-08 — 决定：强化剂保留独立分类。
  - 原因：项目现有 18 个强化剂条目仍属于图鉴内容，用户没有要求移除。

## Discoveries

- 战略配备分类不能只依赖 `offensive` 标签：MS-11 的交互方式更符合人工操控绿色战备。
- 当前标签已足够区分蓝色战备的三号位与背包组合，无需修改 `data.js` 或装备 ID。

## Risks / Open Questions

- “炮塔战备”需要容纳自动地雷和护盾设施。缓解：UI 副标题明确为自动部署类，并在代码注释记录边界。非阻塞。
- 右侧入口列在手机上若保持桌面尺寸会遮挡内容。缓解：手机断点缩小并贴右排列，敌人展开时隐藏整列。非阻塞。
