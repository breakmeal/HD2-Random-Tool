# 敌人档案分屏扩张导航 ExecPlan

状态：Active
创建日期：2026-08-08
最后更新：2026-08-08 12:20

## Purpose / Goal

把现有“敌人档案”右侧抽屉重构成一个具有阵营对立感的分屏界面。默认状态下，页面右侧显示带背景图的“敌人”平行四边形入口；悬停时入口高亮。点击后敌人界面从右向左扩张，原装备终端内容隐去，左侧改为只显示写有“超级地球”的返回平行四边形。

## Requirements

- [x] 页面右侧提供带敌军背景图的平行四边形“敌人”入口。
- [x] 敌人入口悬停或键盘聚焦时明显高亮，并保持可读的中英辅助文字。
- [x] 点击入口后，敌人区域从右向左扩张，原装备终端内容隐去；桌面左侧仅保留约八分之一宽度。
- [x] 展开后左侧只显示写有“超级地球”的平行四边形返回入口，点击可恢复默认页面。
- [x] 展开/收起状态具备正确的 `aria-expanded`、`aria-hidden` 与焦点行为，ESC 可收起。
- [x] 覆盖三大阵营的敌人条目，至少包含 Terminids、Automatons、Illuminate。
- [x] 每个敌人条目展示图片、血量、弱点等信息。
- [x] 未能可靠确认的数据必须留空或标明待核实，不凭估算补数。
- [x] 桌面宽度形成可见的左右分屏；手机宽度改为敌人界面覆盖主内容，避免把主页面压缩到不可用宽度。
- [x] 敌人图标加载失败时，卡片显示纯色图像不可用状态，不再使用抽象背景图。
- [x] README、AGENTS.md 与本计划准确描述新的显示方式、脚本顺序和验证结果。
- Out of scope: 战斗模拟、AI 选择、网页跳转到独立页面。

## Current State

- `index.html` 当前在顶部工具栏提供“敌人档案”按钮，并以 `.enemy-overlay > .enemy-drawer` 承载敌人界面。
- `app.js` 负责随机装备、军备库、图鉴筛选与装备详情；图鉴详情当前以内联方式展开。
- `codex-v2.js` 会覆盖 `codexCard`、`renderCodex` 和详情打开逻辑，旧的右侧装备抽屉已被停用。
- `enemy-dossier.js` 维护独立 `enemyState`，通过给 `.enemy-overlay` 添加 `open` 类控制分屏；阵营、搜索、竖卡和点击放大详情均在该文件中维护。
- `enemy-dossier.css` 当前将敌人界面设为桌面 87.5% 宽度的分屏舞台，卡片为竖直封面，详情使用遮罩式放大面板。
- `enemy-data.js` 包含 51 个敌人条目；图片通过 Helldivers Wiki `Special:FilePath` 加载。
- 项目有 199 件装备和 199 张本地装备图片；`node scripts/validate-data.mjs` 当前无错误。
- `PLANS.md` 规定这类跨 HTML / CSS / JS / 数据的工作需要独立 ExecPlan。

## Implementation Plan

1. 生成并保存敌人入口/面板使用的无文字战场背景图，确保文字和交互仍由 HTML/CSS 控制。
2. 调整 `index.html` 页面壳层：把超级地球内容包进可收起舞台，移除顶部旧入口，增加右侧“敌人”平行四边形入口和展开后替代原内容的左侧“超级地球”返回入口。
3. 重构 `enemy-dossier.js` 的开关逻辑：同步页面壳层、ARIA、焦点、滚动和 ESC 行为，保留阵营、搜索及卡片渲染。
4. 重写 `enemy-dossier.css` 的布局与动画：桌面分屏扩张、入口高亮、左侧返回入口，以及 700px 以下覆盖式手机布局。
5. 更新 README、AGENTS.md 和本计划，删除“独立右侧抽屉”的过时描述并记录新交互边界。
6. 运行语法检查、数据校验和浏览器回归，验证默认/展开两种状态、桌面/手机断点、键盘关闭和控制台。

## Decisions

- 2026-08-08 — 决定：敌人档案采用独立右侧抽屉，不继续扩展现有装备图鉴的卡片内展开。
  - 原因：用户明确要求“不要继续在此页面上添加”，而且现有图鉴已经有专门的覆盖层逻辑。
  - 影响：需要新增独立 DOM、样式和事件处理，避免和 `codex-v2.js` 的图鉴覆盖层互相干扰。
- 2026-08-08 — 决定：敌人数据从 Helldivers Wiki 页面原文自动提取。
  - 原因：页面原文已包含 `Infobox Enemy` 与 `Anatomy Table`，适合稳定提取图片、血量和弱点。
  - 影响：需要新增生成脚本或等效数据构建步骤，并在文档里注明来源。
- 2026-08-08 — 决定：保留现有敌人数据，只替换为竖直封面卡并增加独立放大详情状态。
  - 原因：用户要求改变的是显示方式，现有 51 条数据、搜索和阵营筛选仍满足内容需求。
  - 影响：避免无关数据变化，也不运行会重写装备详情和图片的采集脚本。
- 2026-08-08 — 决定：初版桌面使用约 42% / 58% 的左右分屏，手机使用覆盖式敌人舞台。
  - 原因：初步将用户描述理解为保留可见的压缩装备页面。
  - 影响：该决定已由后续用户反馈取代。
- 2026-08-08 — 决定：桌面展开态改为约 26% / 74%；左侧仅显示“超级地球”返回平行四边形，原装备内容不参与展示。
  - 原因：用户确认完整装备内容仍占据左半页并不符合预期。
  - 影响：敌人卡片区域得到更多宽度，且左侧保留清晰、单一的返回动作；700px 以下仍使用覆盖式敌人舞台。
- 2026-08-08 — 决定：桌面展开态调整为约 12.5% / 87.5%，图片失败时保留 `<img>` 并切换到本地背景资源。
  - 原因：用户反馈左侧仍过宽且图片全部丢失。
  - 影响：左侧返回面板改为更紧凑的竖向布局；远程敌人图标不可用时仍有本地图像可见。
- 2026-08-08 — 决定：以新的分屏扩张舞台取代旧版覆盖式右侧抽屉；旧“独立抽屉”决定保留在日志中但已被本决定取代。
  - 原因：用户明确要求点击平行四边形后敌人区域扩张并压缩原装备页面。
  - 影响：`.enemy-overlay` 仍保留名称以减少 DOM 改动，但语义和样式已经是可变宽度的第二舞台。
- 2026-08-08 — 决定：背景最终使用项目本地绘制的 SVG，并栅格化为 1600×900 PNG 供页面加载。
  - 原因：内置图片生成结果无法导出到仓库，Helldivers Wiki 下载又因网络审批服务不可用而被拒绝；本地资源无远程失效风险。
  - 影响：背景不作为游戏资料依据，`SOURCES.md` 已明确其仅为抽象界面美术。

## Discoveries

- 2026-08-08：`codex-v2.js` 会直接重写图鉴卡片和详情逻辑，不能把敌人档案挂到同一套内联详情上。
- 2026-08-08：Helldivers Wiki 敌人页面 raw 文本可直接读取 `Infobox Enemy`、`Anatomy Table` 与阵营目录。
- 2026-08-08：README、AGENTS.md 和旧 ExecPlan 都把现有实现描述为右侧滑入抽屉，需要随本次重构同步更新。
- 2026-08-08：浏览器自动化仍被安全策略拒绝访问 `http://127.0.0.1:4173/`，不能通过切换浏览器或其他自动化方式规避；已改用静态结构校验与隔离的开关状态测试。
- 2026-08-08：`http://localhost:4174/` 可用于回归；桌面与 390px 手机视口均验证无横向溢出，卡片图片与详情图片成功加载。

## Risks / Open Questions

- 生成背景图不能包含可读文字或官方标志，以免和 HTML 标签冲突；文字统一由页面渲染。非阻塞。
- 桌面主页面压缩后，原有四列装备布局会依据容器宽度变窄；通过分屏态的专属网格规则降为单列/双列缓解。非阻塞。
- 所有已核验敌人条目当前使用本地刷新 PNG；图片失败时只显示纯色占位。非阻塞。
- 真实浏览器中的动画观感、断点重排和远程敌人图标加载仍待用户可访问本地页面的环境确认。影响：计划暂不标记 Complete；当前代码通过静态和状态逻辑验证，不阻塞交付试用。

- 数据生成后检查敌人数据摘要、图片数量与缺图数量。
- 浏览器验证：
  - 右侧入口悬停/聚焦高亮，点击后向左扩张。
  - 主页面在桌面端被压缩且仍可见，点击“超级地球”恢复。
  - 三大阵营切换正常。
  - 图片、血量、弱点、弱点高亮可见。
  - ESC、ARIA 与焦点恢复正常。
  - 桌面与手机宽度不横向溢出，控制台无项目自身错误。

## Outcome
